## Scope and severity

Reviewed the fetched development baseline (`be522f2`), subsequent release history through `3f4ea30`, the GitHub Wiki, effective API routing, Admin authentication/upload boundaries, media/recording storage and transactions, control audit, deployment and CI contracts. The initial local checkout `b20db44` was behind; already-fixed defects there are not counted as current defects. The review then exercised a private-CA HTTPS development environment with one Master, three Direct Followers and six Relay Followers.

P0 means a demonstrated critical emergency such as broad unauthenticated takeover, catastrophic data loss or unconditional service outage in the supported deployment. P1 means a high-impact defect needing prompt remediation. P2 means a concrete defect with narrower impact or specific prerequisites. P3 means low-risk documentation/operability drift. Priority is not a CVSS score, and non-security defects are not claimed to be CVEs.

**Confirmed P0: 0.** This means no P0 was demonstrated within this review, not that the entire project is proven vulnerability-free. No production environment was inspected or modified, and no exhaustive penetration test is claimed.

## Findings and fixes

| ID | Direction / priority | Evidence and impact before repair | Repair and regression |
|---|---|---|---|
| S-01 | Security / P1 | FastAPI parsed multipart upload bodies before executing session/CSRF dependencies. An anonymous HTTPS upload consumed the request stream before returning 401. The upload Nginx location permits bodies up to 8705 MiB and parsing spools files, so repeated anonymous requests can consume temporary storage. No destructive disk-fill test was performed. | ASGI upload gate checks transport, session and CSRF before reading any body. Existing endpoint checks remain, so an expired/revoked session is rechecked after upload. Tests assert zero body reads for anonymous/invalid-CSRF requests and preserve valid upload handling. |
| S-02 | Security / P2 | When a loopback reverse proxy is configured as trusted, the unconditional peer-loopback exception accepted a remote HTTP client despite `X-Real-IP` identifying a remote address. This is a custom-proxy condition, not the default Docker proxy topology. | A recognized proxy must report HTTPS. Direct loopback recovery is allowed only without forwarding headers or invalid proxy identity. Existing direct HTTPS and trusted HTTPS-proxy tests remain. |
| S-03 | Security / P2 | Current Trivy data reported eight High Alpine package findings with fixed versions in the pinned Nginx image. The findings affect `libexpat`/`libuuid`; no FrontierCloud exploit path was demonstrated. The same scan reported Debian runtime findings without vendor-fixed packages and two Python packages from embedded third-party SBOM data that runtime metadata proved were not installed. | Run `apk upgrade --no-cache` while building Nginx, then rescan the built image. Python project resolution also passed `pip-audit` with no known vulnerabilities. Unfixed Debian base findings remain tracked upstream; this review does not relabel scanner severity as demonstrated application impact. |
| F-01 | Functionality / P2 | Authenticated password change with a valid current password and a policy-invalid new password raised uncaught `ValueError`, returning 500 and missing a failure audit. | Return 400, persist a `password-policy` failure reason, never include either password in audit. |
| F-02 | Functionality / P2 | A recording with the optional trailer magic and malformed JSON/UTF-8 raised after bytes were published or during stat/finalize. Non-finite lyric timestamps survived validation and could fail JSON serialization. | Ignore malformed, deeply nested, overflowing or non-finite optional metadata; retain audio. Valid metadata round-trip tests remain. |
| F-03 | Functionality / P2 | On a cold usage cache, deletion scanned the remaining bytes then subtracted the deleted size again. Reproduction: delete 3 bytes from 8 total, reports 2 instead of 5. Account-directory deletion had the same defect. | Invalidate the cache after removal; next read counts remaining files once. Tests cover cold file deletion and warm/cold account deletion. Durable SQL quota reservations remain a separate control. |
| F-04 | Functionality / P2 | A Windows checkout with CRLF shell files built a Nginx image that repeatedly exited 127 (`15-select-tls.sh: not found`) on the Ubuntu test host. Repository shell blobs used LF but lacked checkout enforcement. | `.gitattributes` enforces LF for shell/AWK files; source regression checks entrypoint bytes. Rebuilt the real image from normalized sources. |
| F-05 | Functionality / P2 | The karaoke page supplied STUN configuration in an executable inline script while production CSP allows only same-origin scripts. Chromium reported a CSP violation, so network observation silently remained disabled. | Store configuration in an inert JSON script and let the same-origin observer parse it. Node and real Chromium tests assert the configured ICE server is used and the karaoke page produces no CSP violation. |
| F-06 | Functionality / P1 | When Follower storage was configured before its first successful heartbeat, the Master persisted `writable=0`. Later healthy heartbeats copied that stale value forever. In the 10-node environment all nine Followers were online with capacity but Direct/Relay uploads returned 409. | Recompute writability from durable `storage_enabled` and current relationship health on every heartbeat. Regression covers online recovery, offline transition and disabled storage. Reapplying configuration restored the running pre-fix environment and all real imports completed. |
| R-01 | Functionality / P1 | An Updater process exit during queued/running/distributing work lost its in-memory task but retained a permanently busy status. During replacement, a crash after removing a container could also leave it absent. A build failure before container snapshots reset the checkout to the target and did not restore the old SHA. | Persist container snapshots before replacement; on restart, detect abandoned work, restore the prior checkout/containers where required, retain maintenance, and mark the operation `failed/interrupted` so the standard release may retry. Container recreation now handles an already-removed target. Tests cover interrupted build, replacement and distribution plus pre-snapshot build failure. |
| R-02 | Functionality / P2 | Concurrent start handling could enqueue work, wake the worker, then overwrite its `running` state with `queued`. | Serialize admission and publish `queued` before waking the worker. A deterministic regression forces the old ordering and verifies `running` is retained. |
| R-03 | Functionality / P2 | `restarting` was omitted from busy-state checks. During the Updater runtime handoff, Admin could report release controls available or allow maintenance to be manually opened. | Treat `restarting` as busy in release and site controls. Tests cover all four busy states: queued, running, distributing and restarting. |
| P-01 | Performance / P2 | Storage stat and Master/Follower recording stat hashed complete files synchronously inside async endpoints. In the supported single-worker model this blocks all other event-loop work during the hash. A thread-identity regression demonstrated the old execution path; no production latency estimate is asserted. | Offload stat hashing to threads, keeping 1 MiB streaming reads. A blocked-hash test demonstrates other event-loop work progresses and verifies exact size/SHA-256. This does not make all filesystem operations asynchronous or eliminate disk contention. |
| A-01 | Audit / P2 | `CancelledError` bypassed `except Exception`, leaving only `pending` for cancelled control actions. A secondary audit exception could also replace the original action exception. | Record `interrupted`, preserve cancellation/original exceptions, and log secondary audit failures. `interrupted` does not assert rollback or prove that an external operation stopped; operators must reconcile state. Abrupt process termination can still leave `pending`. |
| D-01 | Functionality / P3 | Wiki described active Compute workers and Rust/WASM karaoke; README still required concrete member selection. Documentation omitted current site-type placement, same-parent folder rename and lyric hierarchy boundaries. | Update README and versioned Wiki sources to current code; clearly separate reviewed code, CI results, merged release and deployed production. |

The seven initial code scenarios were executed against unmodified code and failed as expected (7 failures and 2 malformed-trailer subtest errors). Existing baseline tests passed: 483 discovered, 4 skipped. The CRLF, CSP and Follower-writability defects were subsequently reproduced in Linux/Chromium or the persistent cluster.

## Verification

Targeted regression file: `tests/test_four_area_audit.py`. Deployment line-ending regression: `tests/test_deployment_contract.py`. Ten-node acceptance: `tests/federation_ten_node.py`.

Final local discovery after integrating the current `dev` head: 514 tests passed, 4 skipped. The exact integrated candidate passed 517 tests on Ubuntu with 1 platform skip after installing its required FFmpeg runtime; the required `dev` workflow rechecks the pushed SHA. Node network-observation smoke, whitespace checks, release policy and deployment contracts also passed. The disposable two-node Chromium suite passed all ten TLS, topology, placement, streaming, lyrics, recording, browser and recovery stages.

The final application candidate also passed the isolated 1 Master + 3 Direct + 6 Relay acceptance. All ten private-CA endpoints passed trust, unknown-CA and wrong-host checks; automatic placement reached all nine Followers; every Local/Direct/Relay object passed exact GET/HEAD/Range checks; Chromium playback, lyrics and microphone recording passed; MySQL/Redis security/concurrency checks passed; and all nine Followers completed a business backup. The subsequent Nginx package-only rebuild passed its image syntax and vulnerability checks separately.

The Ubuntu acceptance runs as root in isolated fixtures while the service keeps its production unprivileged Web UID. OpenSSL generates the CA and leaf certificates; Python and Web/Nginx use a CA bundle, and Chromium uses an isolated NSS trust store. Unknown CA and wrong hostname are negative checks; the harness does not use `verify=False`, `ignore_https_errors`, or a blanket certificate bypass.

The persistent environment retains one Master, three Direct and six Relay Followers, each on an isolated Docker daemon so the released Updater can use its production container names. It imported 671 MP3, 668 MP4 and 360 distinct LRC files through Admin transactions: 1,699 objects and 16,249,624,613 bytes. The files are development data and are not committed. All nine Followers completed business backups.

A bounded real-data load run issued 1,200 concurrent 1 MiB Range requests with 48 workers across 1,339 audio/video objects. All returned the requested bytes: 1,255,785,544 bytes in 7.107 seconds (168.84 requests/s, p50 186.43 ms, p95 557.27 ms, maximum 696.59 ms). On this single physical host, that is regression evidence rather than a network or production capacity claim. The same run stopped one Direct Web service until the Master marked it offline, confirmed unrelated media remained readable, restarted it and verified owned-media recovery; it also stopped/restarted Master Redis and MySQL separately and verified readiness plus 30 random objects afterward.

Version management was exercised from initial `b20db44`: the standard Admin **upgrade-and-distribute** endpoint converged all ten application and Updater runtime SHAs to `3f4ea30`; the standard rollback endpoint converged all ten back to `b20db44`; the root-owned CD reconciliation service then called upgrade-and-distribute and restored all ten to `3f4ea30`. The CD timer runs every ten minutes and fails closed unless the current `main` satisfies repository promotion and exact-`dev`-CI provenance.

## Reproduction

On the root-owned disposable Linux Docker host, with Python `httpx` and Playwright/Chromium plus OpenSSL and `certutil` installed:

```bash
docker build -t frontiercloud-acceptance-web .
docker build -t frontiercloud-acceptance-nginx -f nginx/Dockerfile .
docker build -t frontiercloud-updater -f updater/Dockerfile .
python -m tests.federation_ten_node --directory /root/frontiercloud-ten-test --keep
```

The fixture directory must be new. The harness uses dedicated `fc-acceptance-ten-*` Compose projects and the test-only `172.30.251.0/24` gateway network; check for collisions before running. `--keep` retains test data, CA private material and containers for inspection; do not publish that directory or secrets. Without it, only the harness-owned Compose stacks and gateway network are removed. Transfer samples are small-file correctness evidence, not a load-test throughput result.

No schema migration is introduced. Existing roles, object IDs, placements and supported single-worker deployment remain unchanged.
